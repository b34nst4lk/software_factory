# Map: Software Factory (pi extension)

## Destination

A working *prototype* of a software factory built on pi: **Wayfinder** (glm-5.2, Ollama cloud) clears requirements/decisions → a new **to-tickets** skill converts resolved decisions into implementation tickets → a **deterministic orchestrator script** (no LLM) drives an **implementer** (deepseek-v4-flash) and a **final verifier** (glm-5.3-flash) as pi agents via **herdr** — with a two-loop TDD inner loop (decision 14) — owning cycle-counting, feedback routing, and human surfacing, with verifier escalation back to Wayfinder. Once the prototype works end-to-end on this repo, it becomes the parameterized base for other projects.

## Notes

- **Domain**: extending pi into a multi-agent software factory.
- **Skills every session should consult**: wayfinder (this map), grilling, domain-modeling, prototype, research, tdd; plus the **to-tickets** skill once built. herdr agent-automation docs: https://herdr.dev/docs/agent-automation/ ; agents: https://herdr.dev/docs/agents/ .
- **Model bindings** (decision 14; cross-model binds the **final** verifier — amended rule below):
  - Wayfinder / grilling / to-tickets sessions → **glm-5.2:cloud** (Ollama cloud; also the model this charter session runs on).
  - Implementer → **deepseek-v4-flash:cloud**, low effort.
  - Inner verifier (TDD teeth-check; gated LLM vacuous-test pass) → **deepseek-v4-pro:cloud** — same family as the implementer; allowed because its judgment is backstopped by the deterministic mutation audit (14 Q5).
  - Final verifier (6-gate adversarial review) → **glm-5.3-flash:cloud** — cross-family vs the implementer (glm ≠ deepseek).
  - Orchestrator → **deterministic script, no LLM.**
  - **Wiring pending (build under 25)**: `deepseek-v4-pro:cloud` + `glm-5.3-flash:cloud` not yet in `~/.pi/agent/models.json` — add decision-02-style; confirm effort control on `deepseek-v4-flash` (low) + `glm-5.3-flash` (low/high/max). `qwen3.5:cloud` is superseded as the verifier (was the prototype verifier through 15/17).
- **Standing preferences**:
  - The verifier **never assumes**. Any ambiguity is escalated back to Wayfinder as a new decision ticket, never guessed. Wayfinder is the single decision channel throughout (continuously interleaved, not a one-shot front-end phase).
  - Cross-model review (amended, decision 14): the **final** verifier is a different model family from the implementer; the **inner** teeth-check verifier may share the implementer's family, backstopped by the deterministic mutation audit.
  - The orchestrator is a deterministic script that "bounces between" the agents and owns the cycle counter, reporting cadence, feedback routing, and human surfacing.
  - Human gates: map→implementation handoff; pre-merge. Verifier-fail → Wayfinder ticket (not auto-retry).
  - Flow: `wayfinder skill → to-tickets skill → orchestrator script → implementer + verifier (via herdr)`.
- **Reuse, don't rebuild**: the factory is a **thin layer over the existing matt pocock skills** (wayfinder, grilling, domain-modeling, tdd, code-review, prototype, etc.). The only new code is the `to-tickets` skill, the deterministic orchestrator script, herdr setup, and the pi provider config (mostly done — 02). Existing skills are reused where they fit (e.g. `code-review` as the verifier's method, `tdd` for the implementer); how the orchestrator/verifier invokes them is a 05/06 design question.
- **Formalize-when-discovered (standing principle)**: anything programmatically checkable (type checking, formatting, tests, code coverage) lives in the **deterministic pre-commit hook**, NOT the LLM verifier; the verifier only does judgment checks (meets-requirement, contradictions, over-engineering, behavior-coverage sensibility, code-review). As we build and discover a check can be formalized, **migrate it verifier→pre-commit** — progressively shrinking the LLM surface. (Decided in 06 Q7.)
- **Execution carried into this map**: iteration 1 is the *prototype*, built here; later iterations are dogfooded (the factory builds its own new features). The map clears the fog so the prototype can be built; the build itself (ticket 07) is the destination artifact, not a separate spec handoff.
- **to-tickets is a thin specialization, not a reuse of the existing skill** (decision, 2026-08-21): the mattpocock pack already ships a general-purpose `to-tickets` skill (tracer-bullet decomposer, loose-prose tickets under `.scratch/<feature>/issues/`), but its output isn't orchestrator-consumable (no machine-parseable frontmatter, no model binding, no value-only-mutation contract, no implementer-prompt body, wrong namespace). The factory `to-tickets` (at `factory/skills/to-tickets/`) keeps the existing skill's *process* (tracer-bullet decomposition, blocking edges, prefactoring-first, quiz-then-publish, one-file-per-ticket) and specializes the *I/O contract* per ticket 04: one-decision-per-invocation, the 04 YAML frontmatter + prose prompt body, `.scratch/<effort>/impl/` location, ≤5 cap, non-overlapping `scope_files`, structured-behavior `acceptance`, per-unit `model` binding. Honors "thin layer, reuse don't rebuild" — we reuse the decomposition logic, specialize the schema.

Inner loop is sub-cycle (no commit/cap/state.db). **Model topology amended**: Wayfinder glm-5.2 / Implementer deepseek-v4-flash (low effort) / Inner verifier deepseek-v4-pro / Final verifier glm-5.3-flash. **Cross-model rule amended**: binds the **final** verifier (glm ≠ deepseek); the inner verifier may share family (deepseek) because its vacuous-test judgment is backstopped by the deterministic mutation audit (formalize-when-discovered). - [25 — two-loop architecture (inner TDD loop + final 6-gate verifier)](issues/25-two-loop-architecture.md): **resolved 2026-08-27 (grilling)**. The mechanism for test-strength evidence (2). One **outer** cycle = (inner loop to all-green across the ticket's behaviors) + (final 6-gate verifier round); the 5-cycle cap counts outer cycles only; inner is invisible (no commit/cap/state.db). **Inner loop = per-behavior micro-cycles**: per behavior Bn — orchestrator prompts implementer "write failing test for Bn only" → runs pytest in the worktree (subprocess) → witnesses red → inner-verifier pane judges test honesty → prompts "implement until Bn green" → witnesses green → judges green honesty. **Deterministic witness = orchestrator subprocess** (guaranteed exit code); **inner-verifier pane = LLM judgment only**, every micro-cycle. **Stall**: 5 attempts per behavior, then a per-behavior human-gate (c/s/w) that does not burn the outer cap. **Red-witness escalation**: test green at base → to-tickets wrote a bad ticket → reuse 06's BLOCK→park→resume. **Topology: one herdr space per work unit, 4 panes** — implementer (deepseek-flash low effort), inner verifier (deepseek-pro), final verifier (glm-5.3-flash), orchestrator output pane (shell pane, orchestrator logs actions via `herdr send-keys`, one-way; not a test runner, not a human shell). Tests run via subprocess; output pane is the live view. Gates stay on the orchestrator's own stdout (05 Q5). **Amends 14 (Q5)**: the inner verifier LLM runs every micro-cycle, superseding 14's "gated behind the audit"; the mutation audit is now an additional deterministic backstop. **Amends 05 Q3/Q4** (cycle definition + inner loop), **05 Q5** (output pane in-space log), **06 Q2/Q3** (stall human-gate + red-witness escalation reuse). Carries the model wiring (`deepseek-v4-pro:cloud` + `glm-5.3-flash:cloud` → `models.json`) and the `sf audit` build. **Build ready (to-tickets → factory).**
