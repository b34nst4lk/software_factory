# Map: Software Factory (pi extension)

## Destination

A working *prototype* of a software factory built on pi: **Wayfinder** (glm-5.2, Ollama cloud) clears requirements/decisions → a new **to-tickets** skill converts resolved decisions into implementation tickets → a **deterministic orchestrator script** (no LLM) drives an **implementer** (deepseek-v4-flash) and **verifier** (qwen3.5) as pi agents via **herdr**, owning cycle-counting, feedback routing, and human surfacing, with verifier escalation back to Wayfinder. Once the prototype works end-to-end on this repo, it becomes the parameterized base for other projects.

## Notes

- **Domain**: extending pi into a multi-agent software factory.
- **Skills every session should consult**: wayfinder (this map), grilling, domain-modeling, prototype, research, tdd; plus the **to-tickets** skill once built. herdr agent-automation docs: https://herdr.dev/docs/agent-automation/ ; agents: https://herdr.dev/docs/agents/ .
- **Model bindings** (cross-model review enforced — implementer ≠ verifier):
  - Wayfinder / grilling / to-tickets sessions → **glm-5.2** (Ollama cloud; also the model this charter session runs on).
  - Implementer → **deepseek-v4-flash** (DeepSeek platform; OpenAI-compatible chat completions + Responses API).
  - Verifier → **qwen3.5:cloud** (Ollama cloud; chosen Ollama-only over qwen3.6, which isn't on Ollama cloud — see 02). Older gen than first discussed, but still cross-model vs the implementer.
  - Orchestrator → **deterministic script, no LLM.**
- **Standing preferences**:
  - The verifier **never assumes**. Any ambiguity is escalated back to Wayfinder as a new decision ticket, never guessed. Wayfinder is the single decision channel throughout (continuously interleaved, not a one-shot front-end phase).
  - Cross-model review: implementer and verifier are different models.
  - The orchestrator is a deterministic script that "bounces between" the agents and owns the cycle counter, reporting cadence, feedback routing, and human surfacing.
  - Human gates: map→implementation handoff; pre-merge. Verifier-fail → Wayfinder ticket (not auto-retry).
  - Flow: `wayfinder skill → to-tickets skill → orchestrator script → implementer + verifier (via herdr)`.
- **Reuse, don't rebuild**: the factory is a **thin layer over the existing matt pocock skills** (wayfinder, grilling, domain-modeling, tdd, code-review, prototype, etc.). The only new code is the `to-tickets` skill, the deterministic orchestrator script, herdr setup, and the pi provider config (mostly done — 02). Existing skills are reused where they fit (e.g. `code-review` as the verifier's method, `tdd` for the implementer); how the orchestrator/verifier invokes them is a 05/06 design question.
- **Formalize-when-discovered (standing principle)**: anything programmatically checkable (type checking, formatting, tests, code coverage) lives in the **deterministic pre-commit hook**, NOT the LLM verifier; the verifier only does judgment checks (meets-requirement, contradictions, over-engineering, behavior-coverage sensibility, code-review). As we build and discover a check can be formalized, **migrate it verifier→pre-commit** — progressively shrinking the LLM surface. (Decided in 06 Q7.)
- **Execution carried into this map**: iteration 1 is the *prototype*, built here; later iterations are dogfooded (the factory builds its own new features). The map clears the fog so the prototype can be built; the build itself (ticket 07) is the destination artifact, not a separate spec handoff.
- **to-tickets is a thin specialization, not a reuse of the existing skill** (decision, 2026-08-21): the mattpocock pack already ships a general-purpose `to-tickets` skill (tracer-bullet decomposer, loose-prose tickets under `.scratch/<feature>/issues/`), but its output isn't orchestrator-consumable (no machine-parseable frontmatter, no model binding, no value-only-mutation contract, no implementer-prompt body, wrong namespace). The factory `to-tickets` (at `factory/skills/to-tickets/`) keeps the existing skill's *process* (tracer-bullet decomposition, blocking edges, prefactoring-first, quiz-then-publish, one-file-per-ticket) and specializes the *I/O contract* per ticket 04: one-decision-per-invocation, the 04 YAML frontmatter + prose prompt body, `.scratch/<effort>/impl/` location, ≤5 cap, non-overlapping `scope_files`, structured-behavior `acceptance`, per-unit `model` binding. Honors "thin layer, reuse don't rebuild" — we reuse the decomposition logic, specialize the schema.

## Decisions so far

- [03 — herdr + pi driver pattern](issues/03-herdr-pi-driver-pattern.md): drive pi workers via herdr Pattern A (agent start/prompt --wait/read); pi is a supported herdr kind with lifecycle hooks after `herdr integration install pi`; model binding via pi `--model`; herdr gives state, the script owns the cycle counter; pi RPC mode is a fallback. Findings: [research/03](research/03-herdr-pi-driver-pattern.md).
- [02 — Wire the three models as pi custom providers](issues/02-model-provider-wiring.md): glm-5.2:cloud + deepseek-v4-flash:cloud already wired under one `ollama` provider; verifier = qwen3.5:cloud (Ollama-only choice; qwen3.6 not on Ollama cloud). One models.json entry to add at build time. Findings: [research/02](research/02-model-provider-wiring.md).
- [01 — Repo bootstrap](issues/01-repo-bootstrap.md): git init `main` (commit `2f6b540`); AGENTS.md, CONTEXT.md glossary, `factory/` scaffold (orchestrator/ + skills/to-tickets/ placeholders), .gitignore. No decisions; pure setup.
- [04 — to-tickets skill design](issues/04-to-tickets-skill-design.md): one decision per invocation; decomposition = non-overlapping file scopes, independently implementable+verifiable, 1 unit = 1 pane + 1 prompt, cap ≤5; output = `.scratch/<effort>/impl/NN-<slug>.md` with YAML frontmatter (id/decision/title/scope_files/acceptance/verify/model/depends_on/status/cycle/last_verdict) + prose prompt body; explicit `/to-tickets <decision>` invocation.
- [05 — Orchestrator script contract](issues/05-orchestrator-script-contract.md): python3 deterministic spine; git-as-state (worktree per unit on `impl/NN`, per-cycle commit, Husky guard util: value-only frontmatter + append-only `run.log` + ruff/black/pytest + **type-check (mypy/pyright) + coverage.py**); cycle = implementer-run + verifier-run, human-gated w/ 5-cycle backstop; pipelined across units, conversation within; herdr sidebar = live view (metadata `$summary`) + stdin gates, no custom TUI; verifier = **6-gate** checklist (meets-req / contradictions→escalate / over-engineering / convention / `/skill:code-review` / **behavior-coverage**); pre-merge = in-pane verifier → PR → Sourcery + human → `gh pr merge --squash` after GitHub approval; skills via `/skill:name` (implementer `/skill:tdd`); `enableSkillCommands: true`. Research: [research/05a-gleam-viability.md](research/05a-gleam-viability.md).
- [06 — Feedback & escalation protocol](issues/06-feedback-and-escalation-protocol.md): verifier verdict = fenced-YAML per-gate (PASS/FAIL-fix/BLOCKED-escalate + overall); on BLOCKED → templated Wayfinder ticket, **park** unit (panes idle, sidebar-attachable) + continue independent units, **file-driven resume**; resolved answer injected verbatim into both implementer+verifier prompts; PR-comment routing (poll `gh api`; merge gate = human APPROVED + Sourcery clean + no CHANGES_REQUESTED; dismiss-via-PR-reply for nonsense comments); model failover = 3 backoff retries then **pause whole orchestrator** (Ollama quota is shared across models); 6th gate = behavior coverage (fuzzing/hypothesis + test↔behavior mapping); **formalize-when-discovered** standing principle.

## Not yet specified

- **Open frontier (live tickets)**:
  - [14 — test-strength: tests must break when the behavior is wrong](issues/14-test-strength-tests-must-break.md) — a grilling that shapes the verifier. **Ripe with new evidence from the 15 build**: the verifier PASSed the `parse_trailer` duplication by *rationalizing* it (never-assume leniency — gate 2 should have BLOCKED for Wayfinder, not explained it away), and a property test had a weak `assume` that Sourcery flagged as flaky.
  - [16 — interrupted-run resumability](issues/16-interrupted-run-resumability.md) — the orchestrator does **not** skip already-done units on restart (no status-seed from the frontmatter); only the per-unit cycle counter resumes. Re-running re-processes everything from scratch.
  - [17 — git-as-state durability: per-cycle commits must land on the impl/NN branch](issues/17-git-as-state-durability.md) — per-cycle commits land, but `git add -A` stages runtime artifacts (`.verdict.yaml`, `run.log`, the `.venv` symlink) → merge conflicts and (2026-08-23) a **broken circular-symlink venv on `main`**. Needs sharpening to "governed state only, not runtime artifacts" + a `run.log` decision. **Starting here next.**
- **New findings from the 15 build (not yet ticketed — candidates)**:
  - `depends_on` doesn't propagate dependency code: `gitops.worktree_add` branches every unit from `main` HEAD regardless of `depends_on`, so a dependent never sees its deps' code (caused the `parse_trailer` duplication, reconciled only at merge). Adjacent to 16/17 — own ticket or fold in.
  - `run.log` tracked-and-merging: kept tracked by design (`!run.log`) but conflicts on cross-branch merges and carries per-worktree state into `main`. Feeds 17.
  - Verifier never-assume leniency (see 14).
