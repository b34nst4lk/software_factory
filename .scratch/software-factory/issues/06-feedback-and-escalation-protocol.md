# 06 — Feedback & escalation protocol

Type: grilling
Status: resolved
Blocked by: 04, 05

## Question

Decide, with the human (grilling), the feedback routing + escalation protocol the orchestrator script enforces (the human's emphasized mechanism):
1. How implementer↔verifier discussion is captured (herdr `agent read` of both panes? a shared scratch file? a structured exchange log?) and routed back to the script.
2. How the script surfaces that discussion + task state to the human (when, in what form).
3. The verifier-escalation path — when the verifier finds a spec ambiguity (no assumptions), the script creates a **new Wayfinder ticket** (grilling/research) in the tracker, blocks the implementer/verifier panes (herdr `agent wait --until`? a pause flag?) until that ticket resolves, then resumes — define the exact blocking/resume mechanism.
4. How a resolved escalation ticket's answer is fed back into the paused implementer prompt.

Resolve by grilling; decision only.

## Grilling decisions (interim — compaction-safe; 06 not yet closed)

- **Q1 — Verifier per-gate verdict format.** The verifier's prompt template instructs it to end every response with a **fenced YAML verdict block**: per-gate `{status: PASS | FAIL | BLOCKED}` with `feedback:` (on FAIL) or `escalation:` reason (on BLOCKED), plus `overall:`. The orchestrator extracts the fenced block (regex) + parses with pyyaml, then routes deterministically: `overall: PASS` → `done` → raise PR; any `FAIL` → collect that gate's `feedback` → next implementer cycle; any `BLOCKED` → escalate to Wayfinder (06 Q2). **Any gate can return BLOCKED** (gate 2 is the dedicated contradictions gate, but e.g. gate 1 can BLOCKED if the requirement is unclear). **Never-assume on parse failure**: if the YAML is missing/unparseable the orchestrator does not guess — it surfaces a human gate ("verifier verdict unparseable") and halts. YAML (not JSON) for consistency with impl frontmatter.
- **Q2 — Escalation mechanism.** On any `BLOCKED`: (1) **Create** — orchestrator writes a **templated** ticket at `.scratch/<effort>/issues/NN-<slug>.md`, `Type: grilling` (default human-gated; wayfinder session may reclassify to `research`), with escalation reason + context (work unit id, gate, verifier verdict, ambiguity). No LLM — orchestrator authors the stub; the human + main-pi/wayfinder session resolves it in parallel. (2) **Block = park, not full halt** — pause that unit's cycle loop, **leave its panes idle** (preserve context), and **continue independent units** (pipelining Q4a; dependents stall by topo). (3) **Resume is file-driven** — on each loop iteration the orchestrator re-scans parked units' tickets; when one flips to `Status: resolved` with an `## Answer`, resume that unit (re-prompt implementer with the answer injected — Q3). No keystroke needed. (4) **Human notification** — herdr sidebar `$summary` `impl-NN BLOCKED → escalated to <ticket-id>` + one-time stdout message. **Idle panes are sidebar-attachable OOTB** (`herdr agent attach <name>`; sidebar lists all panes incl. idle/done) so the human can inspect parked context anytime — confirms "leave idle" over tear-down for the prototype.
- **Q3 — Resolved-answer re-injection.** On resume the orchestrator reads the escalation ticket's `## Answer` (parse the markdown section; deterministic, no LLM) and, for each resumed cycle, **prepends a `Resolution (ticket <id>): <answer>` block to BOTH the implementer and verifier prompts** (implementer implements the clarified requirement; verifier verifies against it). Verbatim injection. **No new frontmatter key** (guard util forbids new keys) — the resolution is **sourced from the escalation ticket**, read at resume and held in memory for the run; a "resolution received" line is appended to `run.log`. **Multi/stacked escalations**: a unit resumes only when **all** its open escalation tickets are resolved, all answers injected; later escalations on other gates spawn new tickets the same way. **If the resolution invalidates the unit** (e.g. "this unit is cancelled; see new unit impl-NN") the orchestrator marks it cancelled and moves on — it does not re-slice (wayfinder + to-tickets' job).
- **Q4 — PR-comment routing.** Orchestrator polls PR reviews/comments via `gh api .../pulls/N/reviews` (~60s cadence); attributes Sourcery by config `sourcery_reviewer_login`, human by their GitHub login. **Merge gate** = human `APPROVED` + Sourcery reviewed clean + no `CHANGES_REQUESTED` from either → `gh pr merge --squash` (Q6); the human triggers it by approving on GitHub. While the gate isn't met: collect all comments (Sourcery + human), format as a `Requested changes on PR #N` block (attributed per reviewer), route to the implementer as the next cycle's prompt (mirroring in-pane `FAIL`); implementer addresses → pre-commit guard → **in-pane 5-gate verifier re-runs** (Q6 invariant: every PR push is 5-gate-green) → push → PR auto-updates → reset poll. `COMMENTED` suggestions route as advisory (don't block the gate; only `CHANGES_REQUESTED` blocks). **Timeouts**: Sourcery ~10min → on timeout surface to human; **no timeout on the human** (human-gated; sidebar reminds). **Dismissal path (human note: comments can be nonsense — AI/human lose context — so pushing back without a change is expected)** — see Q4-dismissal confirmation.
- **Q4-dismissal — "push back without a code change" mechanism.** The implementer's fix-cycle output is **structured** (fenced YAML, mirroring the verifier verdict): per comment `{action: addressed | dismissed, reason?: "..."}`. Orchestrator routes deterministically: `addressed` → commit (pre-commit guard) → in-pane 5-gate verifier re-runs → push; `dismissed` → orchestrator posts the `reason` as a PR reply (`gh pr comment` / reply-to-thread), **no code change, no push**. The human can also dismiss directly on GitHub by resolving the conversation (poll sees it resolved). A dismissed comment may be re-raised (re-enters as `CHANGES_REQUESTED`) or accepted (resolved); the merge gate still governs. **PR-stage backstop = the human** (no numeric cap; `APPROVED` ends it, or escalate to Wayfinder).
- **Q5 — Model failover / quota exhaustion.** Distinguish **model-call failure** (herdr command error / exit 1 / pane not responding — model unreachable) from **verifier BLOCKED** (model ran, flagged ambiguity) — different paths. **Transient failures**: 3 retries with exponential backoff (5s → 15s → 45s). **Quota exhaustion**: Ollama quota is **shared across all models**, so swapping is pointless — after the 3 retries, **pause the entire orchestrator** (quota is global; a per-unit pause won't help). No model swap. Panes left idle (sidebar-attachable per Q2). Surface via sidebar `$summary` + stdin gate `paused: Ollama quota exhausted; (r)etry / (q)uit`; the human resumes with `r` (orchestrator probes quota, resumes if back else re-pauses). Logged to `run.log`.
- **Q6 — Verifier "sensible coverage" = behavior-driven, ticket-grounded.** Tickets (impl Work Units) carry the behaviors: `acceptance` (04 schema, amended) becomes a structured list of user stories/actions → behaviors → success/failure outcomes. Implementer writes behavior-driven tests + property/fuzz tests (hypothesis) probing the behavior space incl. failure states. Verifier's **6th gate — behavior coverage**: (a) possible behaviors captured (fuzzing/hypothesis explores the space; flag un-handled behaviors esp. failure/edge states the ticket named); (b) test cases map back to the behaviors (traceability — every test→a behavior, every behavior→tests; no orphans, no untested behaviors). Q2-B "no vacuous/gamed tests" falls out (gamed tests don't map to real behaviors). **Tooling**: hypothesis for Python (prototype's first target / dogfood); target-language equivalent (fast-check JS, etc.) for other repos — gate is tool-agnostic. Grows the verifier to **6 gates** (was 5) → updates the 05 contract to all-6-gates-pass.
- **Q7 — Formalize-when-discovered principle (standing).** Anything programmatically checkable — type checking, formatting, tests, code coverage — is done in the **pre-commit hook (deterministic)**, NOT the LLM verifier. The verifier only does **judgment** checks (meets-requirement, contradictions, over-engineering, behavior-coverage sensibility, code-review). Boundary: pre-commit *runs* all tests incl. hypothesis + *measures* coverage (deterministic pass/fail + %); the verifier *judges* coverage sensibility + behavior mapping. As we build and discover a check can be formalized, **migrate it from verifier (LLM) → pre-commit (deterministic)** — progressively shrinking the LLM surface. **Pre-commit scope expanded** beyond 05 (ruff/black/pytest + guard util): add **type checking** (mypy/pyright) + **coverage** (coverage.py, threshold-enforced). Gate 4 (coding convention) is mostly pre-commit (ruff/black); the verifier only checks non-automatable convention.

## Answer

Resolved 2026-08-19. The feedback routing + escalation protocol the orchestrator enforces, by question:

- **Q1 Verifier verdict format**: fenced YAML per-gate verdict block (PASS/FAIL-with-fix/BLOCKED-with-escalation + `overall`); orchestrator parses with pyyaml, routes deterministically; unparseable → human gate (never-assume).
- **Q2 Escalation**: on any BLOCKED, orchestrator writes a templated Wayfinder ticket (`.scratch/<effort>/issues/NN-<slug>.md`, Type: grilling by default); **parks** the unit (panes idle, sidebar-attachable via `herdr agent attach`) and **continues independent units**; **file-driven resume** (re-scan tickets each loop; on `Status: resolved` + `## Answer`, resume); sidebar `$summary` + one-time stdout notify.
- **Q3 Resolved-answer re-injection**: on resume, read the ticket's `## Answer`, prepend a `Resolution (ticket <id>): <answer>` block to **both** implementer and verifier prompts (verbatim); held in memory + logged to `run.log` (no new frontmatter key); multi-escalation waits for all; resolution may cancel the unit (orchestrator marks cancelled, doesn't re-slice).
- **Q4 PR-comment routing**: poll `gh api .../pulls/N/reviews` (~60s); merge gate = human `APPROVED` + Sourcery clean + no `CHANGES_REQUESTED` → `gh pr merge --squash`; route comments to implementer as fix cycles; in-pane 6-gate verifier re-runs before each re-push; `COMMENTED` suggestions advisory (don't block); Sourcery ~10min timeout, no human timeout.
- **Q4-dismissal**: implementer's fix-cycle output is structured YAML per comment `{addressed | dismissed, reason}`; `dismissed` → orchestrator posts the reason as a PR reply (no push); human can also resolve conversations on GitHub; PR-stage backstop = the human.
- **Q5 Model failover**: distinguish model-call failure from verifier BLOCKED; 3 exponential-backoff retries (5/15/45s); on persistent/quota exhaustion (Ollama quota is **shared across all models** → swapping pointless) **pause the entire orchestrator**, panes idle, stdin gate `(r)etry/(q)uit`, human resumes; logged.
- **Q6 Behavior coverage**: tickets carry stories→behaviors→outcomes (04 `acceptance` amended to structured); 6th verifier gate — (a) behaviors captured via fuzzing/hypothesis, (b) tests map back to behaviors. Grows verifier to **6 gates**.
- **Q7 Formalize-when-discovered**: programmatic checks (type/format/test/coverage) live in **pre-commit** (deterministic), not the verifier; verifier only judges; pre-commit scope expanded (add mypy/pyright + coverage.py); migrate checks verifier→pre-commit as they become formalizable (standing principle).
