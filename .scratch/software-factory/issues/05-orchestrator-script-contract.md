# 05 — Orchestrator script contract

Type: grilling
Status: resolved
Blocked by: 03, 04

## Question

Decide, with the human (grilling), the deterministic orchestrator script's contract (no LLM):
1. Language — bash / python / node — and why.
2. State model — per-implementation-ticket state, implementer/verifier pane ids, the **cycle counter** and what counts as a cycle (see Not yet specified).
3. Main loop — read next implementation ticket → spawn implementer (deepseek-v4-flash) + verifier (qwen3.6) panes via herdr → count cycles → on worker settled, read output → route state + implementer↔verifier discussion back to the script → surface to human.
4. Human-surfacing form — CLI log stream? a live state file? a TUI? — and exactly what the human sees (state, discussion, cycle count).
5. The pre-merge gate — what must pass before the script presents merge-ready output to the human.

Resolve by grilling; decision only.

## Grilling decisions (interim — compaction-safe; 05 not yet closed)

- **Q1 — Language: python3.** Parses 04 YAML frontmatter natively (pyyaml present), drives herdr via `subprocess`. State-machine seam isolated for a possible future Gleam rewrite if the orchestrator grows into typed parallel panes (Q4 future parameter). Research: [research/05a-gleam-viability.md](../research/05a-gleam-viability.md).
- **Q2 — State & storage: git-as-state, not a run-state file.** Per work unit → its own git worktree on branch `impl/NN` (isolated checkout; eliminates the shared-checkout collision research/03 flagged; unlocks Q4 parallel cheaply). Per cycle → one commit on `impl/NN` = implementer code change + impl frontmatter value updates + appended `run.log` lines. Strict Husky pre-commit hook (repo-wide, active in worktrees) runs: (1) a python **guard util** — impl `.scratch/<effort>/impl/*.md` frontmatter changes are **value-only** (key set unchanged, prose body unchanged); `run.log` is **append-only** (no `-` lines); (2) ruff/black on staged `.py`; (3) pytest. No `run.json`: current state read from impl frontmatter; history = `run.log` (narrative) + git log (structural). Pre-merge gate (Q6) = human reviews `impl/NN`, merges to `main`, `git worktree remove`.
  - **A (04 schema amendment, confirmed)**: to-tickets authors **all keys up front with default empty values** so orchestrator mutations are strictly value-only — adds `cycle: 0` and `last_verdict: ""` to 04's schema. Applied to 04's answer.
  - **B (TDD cycle boundaries, confirmed)**: every `impl/NN` commit is **unit-green + quality-clean + state-guarded** regardless of verifier verdict. Implementer must land green (no cheating) before handing to verifier; verifier must ensure test **coverage** is sensible (a verifier responsibility → folds into 06 / Q7 `tdd` reuse). Distinction: unit-test green ≠ verifier-pass; a verifier-fail cycle still commits as long as unit tests are green.
- **Build note (07)**: adds surface — Husky + python-flavored hooks (adapt the JS/Prettier/tsc-oriented `setup-pre-commit` skill for ruff/black/pytest), the guard util, the worktree workflow.
- **Q3 — Verifier-fail retry & cap: human-gated via a visible per-cycle lifecycle, not a hard stop.** Two branches: verifier **fail-with-concrete-fix** → route feedback back to the implementer as the next cycle (the implementer↔verifier loop); verifier **blocked/ambiguous** → **no retry**, escalate to Wayfinder (06, the "never assumes" rule). This refines the map's standing "verifier-fail → Wayfinder ticket (not auto-retry)" — concrete-fix fails retry; only ambiguous failures escalate without retry. No fixed numeric cutoff does the gating: after every cycle the orchestrator shows the human the **lifecycle of each iteration** (per work unit: each cycle's implementer attempt + tests-green + verifier verdict, rendered from the same facts committed to `run.log`/frontmatter), and the human gates continuation (continue / stop / escalate). **Backstop**: a high default ceiling of **5 cycles** that forces a human surface if unattended; overridable once the human is looking. The lifecycle-of-each-iteration display is carried into Q5 as its centerpiece.
- **Q4 — Main loop & concurrency.** Algorithm: glob impl files → parse frontmatter → topo-sort by `depends_on` → for each ready unit `git worktree add ../sf-impl-NN -b impl/NN` from main → cycle loop (start implementer pane `--model deepseek-v4-flash:cloud`, prompt with unit body + prior verifier feedback on cycle>1, `--until done`, read → start verifier pane `--model qwen3.5:cloud`, prompt with implementer output + `verify` criteria, `--until done|blocked`, read → branch on verdict per Q3 → commit the cycle per Q2 → render lifecycle + gate human per Q3/Q5) until done/human-stop/ambiguous-escalate → on done leave branch for pre-merge (Q6). **Q4a = pipelined**: next work unit starts when the current reaches `done` (verifier-passed), not after merge — multiple `impl/NN` branches may be open awaiting human review; the implementer stays busy while the human reviews at their own pace. **Q4b = conversation within a unit**: one implementer ↔ one verifier strictly alternating (never parallel); parallel is only ever multiple work-unit pairs, each its own worktree.
- **Q5 — Human-surfacing (thin-layer: herdr is the live UI; no custom TUI).** herdr's sidebar (state rollups across panes/tabs/workspaces) is the live per-agent + per-work-unit view, OOTB once `herdr integration install pi` gives authoritative pi lifecycle state. The orchestrator pushes per-cycle facts into the native sidebar via `herdr pane report-metadata <pane> --token summary="impl-NN cN <verdict>"` (renders as `$summary`). `herdr agent wait --until blocked` is the OOTB signal for the verifier's ambiguous/escalate case (06); `done`/`idle` + `herdr agent read --source recent-unwrapped --lines N` is the OOTB read. The orchestrator's own stdout/stdin is **gates only** — minimal plain-text prompts (`c`=continue / `s`=stop / `w`=escalate-to-wayfinder / `m`=merge / `q`=quit) blocking on stdin, plus a one-line queue print (topo/awaiting-merge). No `textual`/`rich` live panel — herdr is the live panel. (Grounded in herdr docs: sidebar rollups, metadata tokens, `agent attach`, `agent wait`.)
- **Orchestrator-necessity reaffirmed (A vs B fork; chose A).** The orchestrator is the thin (~150–250 line) deterministic spine, necessary precisely because it's the only component that can *guarantee* the invariants an LLM can't hold reliably: cycle counting + 5-cycle backstop, cross-model binding every cycle, verdict routing by tag, git-as-state integrity (per-cycle commit + guard util), queue topo-sort + worktree lifecycle + pipelining. herdr is the muscles+display (runtime, no workflow logic); main-pi/wayfinder is the brain (decide + handle ambiguity); the orchestrator is the spine. Scope is minimal by design: it does NOT decide what to build or how to handle ambiguity — only runs the per-unit deterministic cycle loop + guards git state. Confirms the standing "no-LLM orchestrator" decision; collapsing into the main-pi LLM (option B) was rejected.

- **Verifier = 5-gate checklist (verifier behavior; formalized in 06).** Each cycle the verifier (qwen3.5) runs: (1) meets the original requirement? (2) surfaces requirement contradictions/callouts that should be escalated? ← the "never assumes / escalate-to-Wayfinder" trigger; (3) over-engineered? (4) meets coding convention? (5) final code review via the existing `code-review` skill (mandatory in-pane — replaces Q6's earlier "optional pre-merge code-review skill"). Verdict is a **per-gate report** (each PASS / FAIL-with-fix / BLOCKED-escalate), refining Q3's routing: any gate FAIL-with-fix → concrete-fix retry; gate 2 BLOCKED → escalate to Wayfinder; all 5 PASS → `done` → raise PR.
- **Q6 — Pre-merge = two-stage review: in-pane 5-gate verifier (build-time) → PR → Sourcery + human (post-PR) → merge.** Confirmed "sorcery" = **Sourcery** (sourcery.ai), the AI GitHub PR reviewer; the human also leaves PR review comments. Flow: all-5-gates-pass → `done` → orchestrator pushes `impl/NN` + opens a GitHub PR (`gh pr create`) → waits for Sourcery's auto-review (poll PR comments/reviews for a Sourcery-authored review, timeout ~10min → on timeout surface to human) + notifies the human to review. **Request-changes routing**: Sourcery or human requests changes → route back to the implementer as another cycle (branch open; implementer addresses → in-pane 5-gate verifier re-runs on the fix commit → pass → push → PR auto-updates → Sourcery + human re-review). Loop until both approve → merge. PR stage is a human-gated cycle loop with Sourcery+human as reviewers, mirroring Q3 (concrete-fix retry; requirement-contradiction → escalate). **Push cadence**: open PR once at first all-5-gates-pass; push subsequent fix commits only. **Invariant**: every PR push is 5-gate-verifier-green. New build prereqs (→ 07 / new ticket): GitHub remote per repo, `gh` CLI auth, Sourcery GitHub App installed. **[(a) resolved: human approves on GitHub; orchestrator polls for GitHub approval + Sourcery-clean → orchestrator runs `gh pr merge` → post-merge smoke on main → `git worktree remove`. (b) resolved: squash; `impl/NN` branch retained, tagged `archive/impl-NN`, for the cycle-history audit trail.]**
- **Q7 — Reusing existing skills: explicit `/skill:name` invocation in the prompt templates.** pi skills register as `/skill:name` commands (confirmed in pi docs/skills.md); the doc says "use `/skill:name` to force it". So the orchestrator's prompt templates embed the slash invocations, not prose: implementer template includes `/skill:tdd` (land green, no cheating); verifier gate-5 includes `/skill:code-review` against the diff. **Build prereq**: `enableSkillCommands: true` in the worker panes' pi config. The orchestrator just passes the prompt body — it stays **skill-agnostic and model-agnostic** (it embeds the `/skill:...` tokens but doesn't interpret them). Concrete skill-reuse bindings (verifier 5-gate checklist + `/skill:code-review` gate 5 + `/skill:tdd` implementer) are formalized in 06.

## Answer

Resolved 2026-08-19. The deterministic orchestrator (**python3**, ~150–250 lines, the thin spine) contract, by question:

- **Q1 Language**: python3 (pyyaml + `subprocess`); state-machine seam isolated for a possible future Gleam rewrite if it grows into typed parallel panes.
- **Q2 State & storage**: git-as-state — per work unit a git worktree on branch `impl/NN`; per cycle one commit (code + value-only frontmatter update + append-only `run.log`); strict Husky pre-commit hook runs a python **guard util** (impl frontmatter value-only + prose body unchanged; `run.log` append-only) + ruff/black + pytest. No run-state file (current state read from frontmatter; history = `run.log` + git log). **04 schema amended**: to-tickets authors all keys up front with default empty values, incl. `cycle: 0` and `last_verdict: ""`, so orchestrator mutations stay strictly value-only.
- **Q3 Retry & cap**: verifier **fail-with-concrete-fix** → route feedback to implementer as next cycle; **blocked/ambiguous** → no retry, escalate to Wayfinder (06). Human-gated via a visible per-cycle lifecycle; **5-cycle backstop**.
- **Q4 Main loop**: glob impl → topo-sort by `depends_on` → worktree per unit → cycle loop (implementer ↔ verifier, strictly alternating) until done/stop/escalate. **Pipelined** across units (next starts at `done`; several `impl/NN` branches open for review). No intra-unit parallel.
- **Q5 Human-surfacing**: herdr sidebar = live view (orchestrator pushes per-cycle facts as metadata `$summary` tokens); orchestrator stdout/stdin = **gates only** (`c`/`s`/`w`/`m`/`q`) + one-line queue print. No custom TUI.
- **Orchestrator necessity**: reaffirmed the thin deterministic spine (option A over collapsing into the main-pi LLM) — it's the only component that can guarantee the invariants (cycle count, cross-model binding, verdict routing, git-state guard, topo/worktree/pipelining).
- **Verifier = 5-gate checklist** (verifier behavior, formalized in 06): (1) meets requirement, (2) requirement contradictions/callouts → escalate, (3) over-engineering, (4) coding convention, (5) `/skill:code-review`. Per-gate verdict; all-5-pass → `done` → raise PR.
- **Q6 Pre-merge = two-stage review**: in-pane 5-gate verifier (build-time) → PR → **Sourcery + human** (post-PR) → merge. Request-changes (Sourcery or human) routes back to implementer as another cycle (PR stage is a human-gated cycle loop mirroring Q3); **every PR push is 5-gate-verifier-green**. PR opened once at first all-5-gates-pass; only fix commits pushed after. Human approves on GitHub; orchestrator polls approval + Sourcery-clean → `gh pr merge --squash` → full-suite smoke on main → `git worktree remove`; branch tagged `archive/impl-NN`. Build prereqs: GitHub remote per repo + `gh` CLI auth + Sourcery GitHub App.
- **Q7 Skills reuse**: explicit `/skill:name` in prompt templates — implementer `/skill:tdd`, verifier gate-5 `/skill:code-review`; `enableSkillCommands: true` for worker panes. Orchestrator stays skill/model-agnostic.
